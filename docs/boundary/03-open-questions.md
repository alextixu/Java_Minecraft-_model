## 第一輪：設計（3 題）

### Q1 SOLID 判斷

我預期照最直接的寫法，會出現三個徵兆：每加一種數值就要在戰鬥處理器加 `if`（O）、核心邏輯綁死在 Minecraft 上而無法測試（D）、一個事件處理器同時管所有效果（S）。

處方是：用 `StatEffect` 介面讓新數值只需新增實作；`core/` 不 import Minecraft；每種效果一個類別。詳見 [01 第 3 節](01-boundary-note.md#solid-判斷第一輪-q1-要確認)。

- **A（建議）** 同意　← **決定**
- B 不是這個問題，是……（請說明）
- C 這次不要重構，直接加

### Q2 Pattern 選擇

會變的是：數值種類、每種數值的戰鬥效果、裝備清單和數值。

- **A（建議）** 原版 Attribute 當底層，加上純 Java 核心（登記表、裝備定義、效果用 Strategy、裝備用 Factory）和 Forge 轉接層。同步、存檔、移動速度效果都交給原版。　← **決定**
- B 完全自製數值系統：自己存數值、自己寫同步、自己套用移動速度。彈性最大，但週五來不及，R5 同步也要全部自己做。
- C 直接寫、不抽象：每把武器一個類別，暴擊和迴避寫在同一個 `if` 裡。今天最快，但做 R4 和 R6 時要大改。

### Q3 變更邊界

**打算動的檔案**（不同意的請劃掉）：

- 新建 `core/`（`stat/`、`equipment/`、`combat/`、`StatReader`）、`forge/`、`content/`
- `build.gradle`：只加 JUnit 測試相依（**已先做**，不影響遊戲本身）
- `.gitattributes`：固定 `gradlew` 用 LF 換行，讓 Linux 和 macOS 能執行（**已先做**）
- `mods.toml`、`pack.mcmeta`、語系檔、物品模型 json
- 刪除 MDK 範例：`ExampleMod.java`、`Config.java`，以及範例方塊、範例食物、範例創造模式分頁

**認為不能動的**（還有要補的請加上）：

- Minecraft 和 Forge 本身（不用 Mixin，也不用 Access Transformer）
- 原版移動速度的計算方式
- `build.gradle` 裡的 Forge 版本和 Java 25 toolchain
- 專案外的 `transcripts/`

**新功能放的位置**：新數值放 `content/ModStats`，新效果放 `core/combat/`，新裝備放 `content/ModEquipment`。

- **A（建議）** 同意　← **決定**
- B 要調整（請寫要劃掉或補上的項目）

## 第二輪：商業規則（4 題，最影響實作的）

### Q4 數值疊加規則和上下限（對應 B2、B3、B4）

例子：主手重劍（−30%），身上穿重甲（−15%）。

- **A（建議）** 百分比修飾**相乘**：0.1 × 0.7 × 0.85 = 0.0595。固定值修飾相加。最後再夾在上下限之間：移動速度不低於基礎值的 30%、迴避率最高 75%、暴擊率最高 100%。　← **決定**
- B 百分比修飾**相加**：0.1 × (1 − 0.45) = 0.055。上下限和 A 相同。
- C 每件裝備自己選要用原版的哪種運算（加固定值、以基礎值為準、乘上總值）。最有彈性，但比較難一眼看出結果。

### Q5 「隨時注入新數值」的意思

Minecraft 的限制：新的數值**種類**一定要重開遊戲才生效；數值的**大小**可以在遊戲中改。

- **A（建議）** 在 Java 程式裡加一行定義（`content/ModStats`），重開遊戲生效。最快、不容易打錯字、也最好測試。　← **決定**
- B 寫在 JSON 設定檔（`config/<modid>/stats.json`），重開遊戲生效。不用重新編譯，示範「注入」比較直觀，大約多花 1～2 小時。核心設計不用改，之後再升級也可以。
- C 遊戲執行中就能新增。原版做不到，需要自製整套數值系統（等於 Q2 選 B），不建議。

### Q6 裝備的數值是共用的，還是每一把各自不同

這題決定之後 R6 在網頁上改數值時，玩家手上那把要不要立刻跟著變。

- **A（建議）** **同種裝備共用一份定義**。改了定義，所有同種裝備（包括已經在玩家手上的）立刻套用新數值。做法是在換裝事件裡動態套用修飾，物品說明（tooltip）由我們自己顯示。　← **決定**
- B **寫在每一把物品上**（原版做法）。每把可以不同，例如隨機詞綴；但網頁改了數值之後，舊的那把不會跟著變。

### Q7 暴擊率和迴避率在週五雛型就要有實際效果嗎

- **A（建議）** 要。暴擊和迴避各寫一個 `StatEffect` 類別，可以示範「新增一個數值加上它的效果，只要多一個類別」。　← **決定**
- B 先只登記數值、顯示在 tooltip，效果之後再做。週五只驗證 T1 的移動速度。
