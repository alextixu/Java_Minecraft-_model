## 第一輪：設計（3 題）

### Q1 SOLID 判斷

照最直接的寫法，我預期會出現這些徵兆：

- 怪物寫在 Java 裡，玩家加一隻要改程式（O）。
- 註冊時把定義包死在生物種類裡，網頁改了也到不了怪物身上（D、S）。
- 把怪物塞進 `WeaponAdmin`／`WeaponApi`，每個認得武器的地方都被迫認得怪物（I、S）。
- 切執行緒、原子寫檔、重新載入各抄一份（S、O）。
- 中立、衝刺寫成 `if` 旗標，行為的 JSON 讀寫寫成 switch（O）。

處方：

- 怪物搬到 JSON，用 id 向 `MobLibrary` 拿現在的定義。
- 新建 `MobAdmin`、`MobApi`。
- 抽三個共用零件。
- 新行為各自是 `Behavior`＋`GoalBinder`，讀寫查對照表。

可以抽成泛型 `DefinitionLibrary<I, D>` 的地方也列出來了，但這次**不抽**，理由見 [21 第 3 節](21-r4b-mob-admin-boundary-note.md#solid-判斷第一輪-q1-要確認)。

- **A（建議）** 同意
- B 不是這個問題，是……（請說明）
- C 這次不要重構，直接加

### Q2 Pattern 選擇

會變的是：怪物清單（玩家加）、每種怪物的定義（網頁改）、行為種類、資料種類（武器、怪物）。

- **A（建議）** 和武器同一套形狀，平行一組怪物類別：
  - 快照式 `MobLibrary`。
  - `MobAdmin`＋`ServerMobAdmin`（Adapter）。
  - `MobSyncChannel`。
  - 沿用 R4 的 Factory 和 Strategy。
  - 只抽三個純搬移的共用零件：`ServerThread`、`AtomicFiles`、可以重新載入的資料。

  武器的程式幾乎不動，約 1～1.5 天。缺點是 `MobLibrary` 和 `EquipmentLibrary` 有約 100 行形狀相同的程式。
- B 泛型化：`DefinitionLibrary<I, D>`、`DefinitionStore`、`DefinitionAdmin`，武器和怪物都是它的實作。重複最少，但要改 R2b 的核心類別和全部武器測試，會和架構師今晚的修改衝突，多約 1 天。
- C 直接寫進武器的類別。今天最快，但之後要拆很痛。

## 第二輪：商業規則（5 題，最影響實作的）

### Q4 範圍

- **A（建議）** 怪物改成 JSON 檔，和武器一樣：
  - 檔案放在 `config/mobarmory/mobs/<id>.json`。
  - 第一次啟動時放入狂戰士、遊擊兵兩個預設檔。
  - 玩家多放一個檔，或在網頁填表單新增，重開遊戲就多一種怪物。
  - 網頁可以改既有怪物的數值和行為。
  - T2 的證明變成「只放一個 JSON，Java 一行不改」。這是使用者 11/07 的主軸。約 1～1.5 天。
- B 怪物維持寫在 Java，網頁只能改既有兩種怪物的數值和行為（A6、A7 做到，T2 維持「加一筆 Java 定義＋重開」）。約半天，但不符合主軸。
- C 網頁只能改既有怪物的數值（只做 A7）。約 2 小時，A6 沒做。

### Q5 行為有哪些選項

我對學長說法的解讀：

- 「中立」是 Minecraft 的中立生物，被打才反擊。
- 「奔跑」是追擊時跑得比走路快。
- 「衝刺」是靠近目標時往前撲一下。

三個都用原版現成的 goal，不寫新的 AI。

- **A（建議）**
  - 攻擊方式三選一：
    - **主動攻擊玩家**：已經有。
    - **中立**：被打才反擊打牠的對象，不主動找玩家。新增，用原版的反擊加近戰。
    - **不攻擊**：兩個都不寫。
  - **奔跑**：攻擊或中立的「追擊速度」倍率，是現有參數。網頁是一個數字欄：1.0 是原速，1.3 以上看起來像在跑。
  - **衝刺**：開關，用原版的撲向目標（`LeapAtTargetGoal`，蜘蛛和狼用的）。
  - **閒晃**：開關，已經有。
  - **追擊距離**：固定 16 格（07 的 O8），不開放設定。
- B 同 A，再加上每種怪物可以設定追擊距離（1～64 格）。學長沒提到；約多 1 小時。
- C 只做「攻擊玩家／中立」開關，奔跑、衝刺不做。範圍最小，但沒做到學長說的「能不能奔跑、衝刺」。

### Q6 改了定義以後，已經在世界上的怪物怎麼辦

（延續 07 的 Q6：「數值立刻生效；行為等下次生成或重新載入」）

- **A（建議）**
  - **名稱、數值、大小**：立刻作用在世界上的同種怪物，和網頁改武器時玩家手上那把立刻變一樣。
  - **行為、裝備**：等那隻怪物下次生成，或從存檔載入（離開再進世界、區塊重新載入）。原版的 AI 是在生物建立時決定的，中途換掉容易出錯。已經拿在手上的裝備不收回。
  - **身體**（殭屍換成骷髏）：等重開，因為渲染器是啟動時決定的。
- B 行為也立刻生效：存檔時把世界上同種怪物的 AI 全部清掉重建。比較直觀，但要處理「正在追玩家時行為被換掉」等狀況，多約半天。
- C 全部都等下次生成，數值也不立刻變。最簡單，但和 07 的 Q6、武器立刻生效的做法不一致。

### Q7 多人同步

（武器在 10 號 Q3 選了 B：伺服器把定義送給每位玩家）

- **A（建議）** 怪物也照武器的做法：
  - 另開一個 `mobarmory:mobs` 頻道，登入時和每次改動後，把全部怪物定義送給每位玩家。其他玩家的電腦上，名稱立刻一致。
  - 數值、大小本來就由原版同步。
  - 怪物種類和身體以每台電腦自己的檔案為準，重開才換。這是平台限制，所以 README 要寫：大家要用同一組 `mobs/*.json`，和武器的規則一樣。
  - 約 2 小時。
- B 不送封包。其他玩家的電腦，名稱以自己的檔案為準；網頁改名後，要等大家重開才一致。數值、大小照樣由原版同步。

### Q8 網頁畫面

- **A（建議）** 和武器分頁同一種排法：
  - **怪物分頁**：架構師的唯讀清單，每一筆加狀態標籤（生效中、待重開、檔案已刪除）。點一隻，打開編輯表單：
    - 名稱。
    - 外觀：身體下拉選單、大小。
    - 數值：登記表的每個數值一行，空白代表用預設值，旁邊寫預設值和上下限。
    - 裝備：每個欄位一個下拉選單，只列在那個欄位生效的武器，加「無」。
    - 行為：「閒晃」勾選；「攻擊方式」三選一；「追擊速度」數字；「衝刺」勾選。
    - 存檔後顯示：「名稱、數值、大小已套用；行為、裝備下次生成；身體要重開」。
  - **新增怪物分頁**：同一張表單，多一個 id 欄。存好顯示「已存成 `config/mobarmory/mobs/<id>.json`，重開遊戲後可以用生怪蛋或 `/summon mobarmory:<id>`」。
  - 錯誤標在欄位旁邊，同武器。
- B 網頁直接編輯 JSON 文字，存檔前用同一套規則驗證。前端最少，但不懂 JSON 的人不好用。
- C 只有編輯，沒有新增；新增只能放 JSON 檔。

## 合併 main `6a3e1fc` 後的調整（2026-11-07，實作者記錄，不用另外決定）

監控 session 說「如果 21～23 有地方要跟著調整，改完在 23 記一行就好」。架構師的段落 A、E 進 main 以後，下面幾處照現況調整，決定的方向不變：

- **原子寫檔不用再抽**：架構師已經抽好了，怪物直接用，`WeaponFolder` 不用動。（當時叫 `data/ConfigFiles`；combo 合併時換成 `JsonFolder`，R4b 合進 main 時 `MobFolder` 跟著改，見 [28](28-r4b-mob-admin-behavior-report.md) 第 9 節。）
- **`web/MobAdmin`、`web/MobJson` 已經存在**（唯讀清單）：R4b 擴充 `MobAdmin`（加讀狀態、存檔、新增、重新載入），不另建介面；`web/MobJson` 的清單欄位全部保留，每一筆加 `name`、`status`、`mob`。檔案格式的讀寫取名 `data/MobFileJson`，避免和 `web/MobJson` 撞名。
- **怪物的路由**：架構師放在 `WeaponApi`，R4b 搬進新的 `MobApi`，由 `AdminHttpServer` 依路徑分給兩個 API。
- **數值改成 JSON 檔**（段落 E）：怪物檔的數值照 `MobArmoryMod.STATS.catalog()` 檢查，所以玩家自己加的數值，怪物檔也能設定。
- **網頁的重新載入**：`POST /api/v1/reload` 的回應不改；怪物另有 `POST /api/v1/mobs/reload`，網頁的同一顆按鈕依序呼叫兩個（O12 不變：一顆按鈕、兩種各自全有或全無）。`/mobarmory reload` 指令一次載入兩種。
- **同步只送名稱**（Q7 A 的範圍不變）：其他玩家的電腦需要的只有名稱（數值、大小由原版同步，行為只在伺服器，身體要重開），所以封包是 id → 名稱。收到的名稱放在另一份表，離開伺服器時清掉，不寫進共用的怪物庫；這是照架構師 `6c01cfd`「登出時還原武器」的教訓：單人遊戲和客戶端共用同一份資料。
- **生怪蛋的外觀**：原版的 `Item.Properties` 沒辦法換預設模型（`item_model` 是在最後依 id 設定的），所以改由執行時資源包產生 `items/<id>_spawn_egg.json`，內容指向原版同身體的蛋。`GeneratedWeaponPack` 原本收「語系檔」一個字串，改成收一組固定檔案（語系檔＋生怪蛋外觀），只改參數型別。新增怪物仍然是 0 個資源檔（O14 不變）。
- **遊戲內測試的設定**：架構師已經把 `src/gametest/config/` 複製到 `run-gametest/config/`（段落 E）。`goblin.json` 放在那裡；兩個預設怪物檔由 `build.gradle` 從 jar 的資源複製過去，不另存一份（O20 不變）。

實作時多記的兩點（照決定的方向，細節由實作者補上）：

- **Q6 A 的裝備**：從存檔載入的怪物，拿的是存檔裡的裝備（R4 原本的規則）。所以改了怪物檔的裝備，只有之後生成的怪物會拿新的；數值、名稱、大小則是載入時就跟著現在的定義。
- **網頁「從檔案重新載入」原本就送不出去**：按鈕送出沒有內容的 POST，伺服器的安全檢查只收 JSON，回 415。這是 R6 時就有的問題，main 上也是這樣。R4b 改成送 `{}`，武器和怪物的重新載入都能用了（在網頁預覽裡實測過）。
